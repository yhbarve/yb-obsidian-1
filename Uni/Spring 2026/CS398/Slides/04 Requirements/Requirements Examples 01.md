# Software Requirements

### Guideline 1: Ask the Model to Identify Stakeholders First, Then Generate Requirements from Each Perspective

**Example:**

> **Problem:** You are building a hospital appointment booking system and have been given a one-line brief. You do not yet know who all the stakeholders are. Use the model to discover the full stakeholder landscape and then generate requirements from each group's perspective.


---

### Guideline 2: Use the Flipped Interaction Pattern to Elicit Requirements Through Structured Questioning

**Example:**

> **Problem:** You are starting a new online library management system. A stakeholder has given you a one-sentence brief: "We need software to manage our library." You need to produce a first-cut Software Requirements Specification, but no further detail has been provided. Use the model to begin eliciting requirements.


---

### Guideline 3: Use the Cognitive Verifier Pattern to Break Ambiguous Requirements into Sub-Questions

**Example:**

> **Problem:** A product owner hands you this requirement: "The system shall send notifications to users." You need to turn it into concrete, testable acceptance criteria. The requirement is intentionally vague as it says nothing about channels, triggers, timing, or user roles. Use the model to produce unambiguous acceptance criteria.
