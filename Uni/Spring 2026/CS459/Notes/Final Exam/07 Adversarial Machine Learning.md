	- Supervised

# Machine Learning as a Service (MLaaS)
- Data gathering and training process can get quite complex, expensive, and time-consuming.
- In particular, this is true for classification where labeling has to be done by humans manually.
- A solution to this is machine learning as a service (MLaaS).
- It offers models as a queryable black box service. For example, ChatGPT or Claude.
- It requires significant computing capabilities to provide accessible service.
- If frequent queries are necessary, it can become quite expensive for the user.
- Leads to issues related to model theft.
- The main motivation behind stealing models is:
	- The actual data gathering and training process is extremely complex, expensive, and time-consuming.
	- You can use models offered by companies using their API services, but frequent queries become quite expensive for the user.

# Model Stealing
- Approximation of the behavior of the model
	- **Objective:** Replicate the functionality of a target model $f(x, \theta)$ without accessing its internal weights or original training data $D$.
	- **Input Collection:** Gather an unlabeled auxiliary dataset $X'$, which can be significantly smaller or drawn from a similar domain.
	- **Label Generation:** Query the target model with inputs $X'$ to produce synthetic labels $Y' = f(X')$.
	- **Surrogate Training:** Train a clone model $f'(x, \theta')$ on the generated dataset $D' = (X', Y')$ to approximate the victim model's decision boundary.
- Defending against Model Stealing
	- It's actually very hard. There is no known effective pure ML defense.
	- A possible solution could be rate limiting, which involves a daily limit for requests. This makes it more time-consuming for a user trying to create a data set using the model API. However, this doesn't solve the problem. It makes it a bit difficult.
	- The legal system may help prevent this.
- The Legal System Angle
	- An ML model can be considered intellectual property if it can prove that someone stole our model. Legal action can be taken against that entity.
	- To prove ownership, we need a method to identify a model, even if it is a stolen copy. We can also prevent misuse, such as deep fakes, by proving that outputs are from a particular model.
# Watermarking
- DNN watermarking is a method designed to detect surrogate models.
- Watermarking embeds a message into a model that is later extractable using a secret key.
- This would allow proof of ownership by proving extraction of the embedded message from the stolen model. Legal action can then be taken.
- A **watermarking scheme** is composed of two procedures: an embedding and an extraction procedure.
	- The embedding procedure takes a watermarking key, a message, and a model and outputs a marked model embedded with the message.
	- Extraction procedure takes a watermarking key, a model, and outputs the message extracted from the model using the key.
- The ideal requirements for watermarking are:
	- Fidelity: The impact on the model's task accuracy is small.
	- Robustness: Surrogate models retain the watermark.
	- Integrity: Models trained without access to the source model do not retain the bottom work.
	- Capacity: The watermark allows encoding large message sizes.
	- Efficiency: Embedding and extracting the watermark is efficient.
	- Undetectability: The watermark cannot be detected efficiently without knowledge of the secret watermarking key.
- Watermarking Categories
	- **During training**
		- **Idea 1:** Create a watermark by assigning arbitrary labels to certain inputs (triggers).
			- Take random images from outside the training distribution, label them randomly, and use these inputs to train the model.
			- To verify, query a model with the trigger input set and check whether it returns the same labels assigned before.
			- For example, while training, give an image of an apple the label "Octopus". The image of the apple is the trigger. During verification, query the model with the apple image as the input and check whether it returns "Octopus" as expected.
		- **Idea 2 - IP Guard:** Deep neural networks have decision boundaries shaped by their parameters. Different models will, by the way, behave differently for some inputs close to the boundary.
			- Search for samples close to the decision boundaries (call them "key inputs") and record their labels.
			- To verify, query a model with the key input set and check how predictions return the same labels assigned before. Verification succeeds if a fraction of predictions (above some threshold) are correct.
			- **Basic idea:** Data points at or close to the decision boundary are often put as different labels by two models that are trained on the same data. For your model, record the exact labels, and during the verification step, check if at least a certain amount of predictions are correct.  
	- **Post training:** White Box Watermark
		- When training a neural network, you add a regularizer penalty to the loss function that forces certain weight values to follow a specific pattern.
		- To detect it, you open up the suspect module's weight file, extract those exact weight parameters, and run a statistical test to see if that artificial pattern exists.
	- **During inference:** Active Watermark
		- You embed a trigger by taking a thousand weird random images and forcing the model to classify them all as stop signs.
		- To detect it, you query the suspect model via its API with those exact 1,000 images. If it flags them all as stop signs, you mathematically prove that it inherited your poisoned training data.
- **Watermarking Example: DAWN**
	- DAWN is an active multi-bit watermarking scheme. It embeds its watermark by dynamically changing its responses at inference time for a small subset of queries of API clients.
	- A small random subset of the inputs provided by API clients are tagged and purposefully misclassified at inference time.
	- The defender memorizes these misclassifications for future verifications. 
	- When given an API to a potential stolen model, the verification procedure queries the API with the saved tagged inputs.
	- During verification, for some model M and all data points or data pairs in the set of tagged inputs, we compute the likelihood of the model reproducing the intentional mistakes. If that likelihood is greater than some threshold, we can conclude that the model was stolen.

# Can an attacker remove watermarks?
- The goal is for the watermark to be removed while retaining a similar test accuracy.
- Fine-tuning and pruning are two examples of basic watermark removal.
- **Fine-tuning** is the process of further training a pre-trained network on a set of new inputs in the same domain.
	- Because this new training data doesn't contain the secret trigger inputs, the network undergoes forgetting, and it updates its weights to prioritize the new task.
	- This effectively erases the forced behavior of the water mark.
- **Pruning** is the process of removing model parameter values according to some heuristic.
	- Pruning uses heuristics to delete low-impact weights or zero out sensitive neurons. 
	- This can disrupt or destroy the specific structural pathways the model relies on to recognize watermark inputs.
- Watermarking deep neural networks is a very active area of research.
- No current watermarking scheme manages to be robust against all watermark removal attacks.
- At the same time, no current watermark removal attack manages to remove all watermarks.

# Evasion Attacks
- These are inference-time attacks. The attacker takes a valid input $x$ and adds small, human-imperceptible perturbations $\delta$ to create an adversarial example $x' = x + \delta$.
- Some examples could be evading a detection system like a facial recognition content filter or fraud detection system.
- The goal is to lower the target model's performance.
## Adversarial Examples
- These are input samples that are crafted for evasion attacks.
- Adversary examples are inputs to machine learning models that an attacker has intentionally designed to cause the model to make a mistake.
- Depending on the objective of the attacker, an adversarial example might have different limitations.
	- **Indistinguishable:** Given a real input, the adversary must generate a visually indistinguishable adversarial input.
	- **Content preserving:** Given a real input, the adversary must generate a new input where the content is preserved.
		- For example, re-uploading movies on YouTube with weird resizing and other effects to trick the detection algorithm
	- **Non-suspicious:** The attacker can produce any input example they wish, as long as it would appear to a human to be a real input.
		- For example, **Voice Assistant attack:** Unlocking a security system or making an unauthorized purchase via audio that appears to be innocuous, such as a voicemail or a television advertisement
	- **Content Constrained:** The attacker can produce any input example they wish, as long as it contains some content payload.
		- Example: email spam
	- **Unconstrained:** The attacker can produce any input they want in order to induce desired behavior from the machine learning system.
		- Example: Unlocking a stolen phone by tricking the fingerprint or face recognition system
- Similar to watermarking, adversarial examples can be considered under different settings.
	- White box means that the model is known by the way.
	- Black box means only query access to the model is available.
	- Transferrable means there is no query access. You craft an adversarial example on a local substitute model you control, and rely on the property that the same trick will **transfer** over to fool the target model as well.
	- Grey box means the rest. **Grey-box** sits right between white-box and black-box. The attacker has **partial knowledge** about the target system, but not full access to its internal weights or architecture. The attacker has limited access, such as the model architecture. 
- Similar to many ML problems, there is no existing defence that can fully prevent adversarial examples.
- For a potential defense, the following properties are required.
	- It preserves clean input accuracy.
	- It correctly classifies adversarial examples.
- An example of a basic defense is **adversarial training**.
	- **Concept:** A data-augmentation defense that trains the model on both clean inputs and dynamically generated adversarial inputs during training.
	- **Mechanism (Batch Level):**
	    1. Take a standard mini batch of samples: $D_i = \{(x_1, y_1), (x_2, y_2), \dots, (x_b, y_b)\}$.
	    2. Generate adversarial counterparts using an attack method (e.g., FGSM or PGD): $D_i' = \{(x'_1, y_1), (x'_2, y_2), \dots, (x'_b, y_b)\}$.
	    3. Update model parameters on the combined dataset: $\overline{D_i} = D_i \cup D_i'$.
	- Adversary training is simple but effective. It is currently considered one of, if not the best, existing defense against adversarial examples by the research community.
