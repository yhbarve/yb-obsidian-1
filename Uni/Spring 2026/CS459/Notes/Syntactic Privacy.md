# Inference Across Multiple Sources
- Inference problem is more severe if the adversary has access to multiple data sources, as long as they can aggregate information across sources.
- External data can be from:
	- Publicly available datasets
	- Purchased datasets
	- Govt. revealed data
	- Large companies collect data which can be hacked into (data leak/breach)
- If datasets contain **veronyms** or **persistent pseudonyms**, one can link data records across these datasets & learn more about an individual or an entity.
	- **Veronyms**: Unique identifiers that explicitly reveal a person's identity (eg: name, ID)
	- **Pseudonyms**: False or fictitious identifiers (eg: username)
- Removing all identifiers from a dataset does not necessarily protect the privacy of individuals. We'll see how in this chapter.
- Simply replacing identifiers with random numbers does not always work. (AOL example)
- Hashing does not make data completely anonymous. For small input spaces, dictionary attacks are pretty easy. (NYC Taxi example)
- Background knowledge relating to the primary data can be used to further de-anonymize records.

# Measuring Privacy
- **Empirically:** Measure the performance of an attack.
- **Theoretically:**
	- **Syntactic:** Measuring a property on the released data **(OUR FOCUS)**
	- **Semantic:** Ensure that the data-release mechanism itself has a property
- - -
# Syntactic Privacy in Relational Databases
- Syntactic notions of privacy define certain properties that the released dataset must satisfy.
- In a relational database / table, the rows are **SAMPLES**, and the columns are **ATTRIBUTES**.
- Attributes can be:
	- **Identifiers:** Uniquely identify an individual
	- **Quasi-identifiers:** In combination with external data, can identify an individual
	- **Confidential:** Contain privacy-sensitive information
	- **Non-confidential:** Are not considered sensitive
- We will always remove identifiers and focus on confidential attributes.
- - -
# System Model
- Each user contributes to a row in the database.
- A data curator releases a sanitized / cleaned version of the database.
- The attacker / adversary sees this sanitized database.
- The properties that we want to enforce:
	- k-anonymity
	- l-diversity
	- t-closeness
- - -
# k-Anonymity
- **Definition: For each published record, there exists at least $k-1$ other records with the same quasi-identifiers.**
- To compute:
	- Group the rows with the same quasi-identifiers. Each group forms an **equivalence class** or **equi-class.**
	- Count the smallest size of a group. That's the k-anonymity.
- To provide k-anonymity:
	- **Remove** a quasi-identifier.
	- **Reduce the granularity** or a quasi-identifier (eg: hiding last character of the ZIP code)
	- **Group** quasi-identifiers (eg: report age as a range instead of actual numbers)
- k-Anonymity is not enough on its own
	- It fails to protect the actual sensitive information attached to an equi-class.
	- If you know that an individual belongs to a particular equity class, you can still learn more about that individual.
	- If all $k$ individuals in a group share the exact same sensitive attribute, your privacy is compromised even if your specific record isn't singled out.
- - -
# l-Diversity
- **Definition: For each quasi-identifier value, there should be at least $l$ distinct values of the sensitive attributes.**
- To compute:
	- Group the rows by the quasi-identifiers to form equi-classes.
	- For each equi-class, count the number of distinct sensitive values.
	- The smallest number of distinct sensitive values is the level of l-diversity.
- To provide l-diversity:
	- Try to make the **equi-classes as large as possible.**
	- Simultaneously, make sure there is **enough variety of sensitive attributes** per class.
- Issues still exist:
	- The data in each equivalence class can be unexpectedly skewed.
	- For example, in an equivalence class with l-diversity of 2, you could still have 99 samples with sensitive attributes equal to **1** and just one sample with sensitive attribute equal to **0**.
	- Technically, you still have two different values for the sensitive attribute.
	- However, the attacker can still create a probability distribution from this data. 
	- Because 99 samples have the sensitive attribute equal to **1**, the overall probability of the sensitive attribute being **1** for that equivalence class is almost 100%.
- - -
# t-Closeness
- **Definition: The distribution of sensitive values in each equi-class is no further than a threshold $t$ from the overall distribution of the sensitive values in the whole dataset.**
- To compute:
	- Organize rows by equi-class.
	- Compute the distribution of sensitive attributes per equi-class and for the whole table.
	- Compute the maximum difference between a class distribution and the whole table on a sensitive attribute. That's the value of $t$.
		- To compute the difference between distributions, we will use variational distance.
		- For two distributions over $m$ values $P = (p_1, p_2, ..., p_m)$ and $Q = (q_1, q_2, ..., q_m)$, $$D[P, Q] = \frac{1}{2}\times \sum_{i=1}^m|p_i - q_i|$$
		- If you have **k** equi-classes, you would have to compute **k** distances and take the maximum of those as the value of **t**.
		- If you have **m** distinct sensitive values, you would have to add **m** absolute value terms to compute each distance. 
- To provide t-closeness:
	- Try to make each equi-class as large as possible.
	- Try to maintain a uniform distribution of sensitive attributes within an equi-class.
	- We can add dummy records to help smoothen the distribution.
- - -
# Limitations
- t-Closeness is overall a reasonable syntactic notion of privacy. It prevents the attacks that we have seen.
- However, these privacy notions require a clear distinction between quasi-identifiers and sensitive values, which is not always possible.
- Computing the optimal k-anonymous dataset is NP-hard.
- These notions of privacy do not provide guarantees against an adversary with background knowledge.
- We need a privacy notion that is adversary-agnostic. A **semantic notion of privacy** that only depends on the mechanism.
